# 通用额度观测工具设计

日期：2026-09-27
状态：用户已批准并授权审核后实施；实现和验证记录见文末。

## 目标与边界

quotacheck 提供完整、可解释、可查询的额度观测数据，使其他人、agent 和脚本能够构建自己的分析与调度工具。成功标准是使用者无需了解本项目的评测流程，就能理解额度含义、获取历史、识别缺口并判断数据是否可用于分析。

用户明确确认：具体能运行多少场评测不是工具职责。任务成本、业务分类、token 权重回归、预测、调度决策不进入核心。初版不扫描 Claude 会话日志，不推断工作目录用途，不提供 forecast。通用任务标记作为后续可选扩展，不阻塞核心交付。

桌面《quotacheck-mcp-改进建议》是问题输入。其中接口字段和当天数值是用户提供的样例，不视为已独立验证的上游契约；实现应采用脱敏 fixture，并记录真实响应与样例之间的差异。

## 当前代码事实

- `src/collectors/claude-code.ts` 显式读取部分字段，未保留完整响应。
- `src/types.ts` 以 session、weekly、subModels 表达额度，缺少单位、来源路径与适用范围。
- `src/collect.ts` 共享文件缓存，但无跨进程采集互斥；Claude 普通缓存 TTL 为一小时，forceRefresh 绕过它。
- `macos/App.swift` 每五分钟强制采集；MCP 与 export-json 也能调用采集器。
- `src/history.ts` 保存真实采集结果（包括错误），而非缓存回退结果，这个语义应保留。写入失败目前静默忽略。
- 历史读取已有原始记录能力，但 MCP 的历史工具只暴露固定七天展示。

## 架构与职责

数据流：来源适配器 → 单一采集协调进程 → 持久化观测/缓存 → 共享查询层 → MCP、CLI、菜单栏、报告。

来源适配器负责凭证获取、请求、脱敏与来源字段解释。协调进程负责调度、互斥、限流和写入。查询层只读取持久化数据，并支持向协调进程提交刷新请求。展示层不能直接采集。

核心调度、存储、查询不依赖 macOS。首个服务管理集成为 launchd，同时提供前台运行命令以供其他平台的进程管理器调用。Keychain 保留为平台凭证适配器；不承诺初版每个来源在所有平台均可用，不支持时返回明确状态。

本地 IPC 使用操作系统支持的本地通道（Unix socket / Windows named pipe），不暴露网络服务。端点位于当前用户数据目录，限制访问。进程获得操作系统互斥后才允许采集；重复启动失败并给出已有服务状态。具体互斥库与通道封装在实施计划中依据项目依赖确定。

## 统一额度模型

新增带 schemaVersion 的观测结构，包含 source、accountKey、observationId、observedAt、limits、extensions、rawRef。accountKey 是非敏感的本地账户分区标识；无法识别账户时标明 unknown，不能宣称已可靠区分换号前后的数据。

每个 limit 包含：

- id：来源与账户分区内的稳定标识，优先使用上游 ID，否则使用规范化 scope、kind 与原始字段路径派生；不使用数组序号或展示名作为唯一身份。
- label：展示名称；原始名称仍保留。
- scope：模型、surface 等上游适用范围，未知维度可保留。
- window：上游报告的窗口类型、开始时间和重置时间；缺失字段保持缺失。
- measurement：可选 used、limit、remaining、utilizationPct，以及明确的 unit/currency。只有百分比时只填百分比，不合成 used=百分比、limit=100。
- provenance：原始字段路径、reported/derived、推导规则版本。derived 数值需说明计算依据。
- upstream：severity、is_active 等来源状态，保持上游含义；不直接把 is_active=false 解释成额度无效。

旧键和 limits 数组可能表达同一额度。仅在适配器有明确对应规则时合并，并保存所有来源路径；无法确认时保留独立记录并标明关系未知，不求和。展示与查询以稳定 ID 区分。

seven_day_breakdown 等构成数据与额度限制分开存放。未知对象原样进入 extensions；可识别的数值对象可以标记为未分类候选，但不能仅凭 percent 字段就断言它是配额。null 与字段不存在保留各自语义。

## 原始数据与存储

默认在启用历史时保留脱敏后的 usage 响应体，提供显式关闭选项。绝不记录请求凭证、Authorization、Cookie、Keychain 内容或完整认证对象。来源适配器在写盘前处理敏感字段，查询原始响应使用相同脱敏数据。脱敏策略版本随记录保存；未知响应仍需通用敏感字段过滤，不能承诺任意未知字段完全不含个人信息。

沿用 JSONL，新增版本化记录，旧月分片只读兼容、不原地重写。新记录按 UTC 日分片，已关闭日分片可压缩；第一版不做“同上”增量编码。原始响应与规范化观测通过 observationId 关联，分别应用可配置保留期。rawRef 对应数据过期时返回 expired 状态。

缓存使用临时文件加原子替换；历史与原始记录只由协调进程追加。崩溃留下的尾部残行可跳过并报告损坏计数。记录写入失败作为存储健康错误暴露，不能继续宣称历史完整。每次真实请求产生采集尝试记录；缓存读取不制造观测。成功但额度不变仍是新的观测。

## 调度与数据质量

每个来源独立配置采样周期，初始目标周期五分钟；周期并非成功采集 SLA。所有调用方共享每来源的 in-flight 请求与 nextAllowedAt。刷新请求合并，普通刷新也不能绕过冷却。

429 的 Retry-After 支持秒数与 HTTP 日期，保存 nextAllowedAt，重启后继续遵守。网络和服务端错误采用有上限的指数退避与抖动。认证失败独立分类并进入需重新认证状态，避免当作限流不断重试；凭证恢复后允许用户发起重试。单个来源阻塞不能阻塞其他来源，超时需要取消实际采集工作，不能只提前返回而让后台请求继续重叠。

状态包含 lastAttemptAt、lastSuccessAt、nextAllowedAt、结构化最近错误、daemon 状态与 storage 状态。错误类别至少为 authentication、rate_limited、network、timeout、unsupported、parse、storage、unknown。错误内容脱敏。

快照 fresh/stale 由实际 observedAt 与配置阈值决定，不由缓存读取时间决定。默认连续十五分钟没有成功样本标为缺口；查询返回缺口边界、已知原因和期望采样周期，缺少证据时原因是 unknown。不把休眠、断网或停机期间补成平坦用量线，不推断精确停机起点。覆盖统计基于成功观测时段与期望采样槽，公开计算规则。

## 查询契约

MCP 与 CLI 复用查询层。新接口返回版本化结构化 JSON；人类可读摘要和图表作为展示能力。

| 接口 | 输入 | 核心输出 |
| --- | --- | --- |
| get_quotas | sources、accountKeys、limitIds（均可选） | 最新额度、观测时间、provenance、freshness 与来源状态 |
| get_history | from、to、sources、accountKeys、limitIds、granularity、cursor、pageSize | 样本或聚合、质量信息、分页游标 |
| get_status | sources（可选） | 服务状态、采集/存储健康、冷却、保留配置、支持的来源能力 |
| refresh | sources（可选） | 各来源 accepted/coalesced/deferred/unavailable、requestId、nextAllowedAt |

get_history 时间范围为 UTC 的半开区间 [from,to)。granularity 首期支持 raw、5m、30m、1h、1d；raw 表示实际样本，不能保证固定五分钟。默认 raw，默认 pageSize=100，最大 1000。按 observedAt、observationId 稳定排序，游标固定查询条件与本次查询记录上界，避免新写入导致重复翻页。

聚合按额度 ID、账户、单位和可识别的重置周期分组，返回 first/last/min/max、样本数量与时间、覆盖和缺口，不默认提供消费量相加结果。不同周期不能混合；周期归属未知时标注 unknown。缺失窗口返回无数据状态，不填零、不插值。

原始响应通过 get_history 的 includeRaw 显式获取，默认关闭并限制该模式每页最多 20 条。响应返回完整分页记录，不静默截断；单条超过传输上限时返回 rawTooLarge 及本地 CLI 导出方式，不丢弃落盘数据。

refresh 为异步请求；调用方通过后续查询查看最新观测及来源尝试状态。服务未运行时返回 unavailable 和启动说明，不偷偷退回客户端直连。

## 兼容与迁移

现有 get_all_quotas 和 get_usage_history 保留工具名、输入和旧输出形状，通过适配层读取新存储；文档明确它们是兼容视图，完整字段使用新接口。旧视图必要的百分比合成行为仅留在兼容适配层，不污染规范化记录。

现有 refresh 的强制直连行为改为统一调度请求，其输出变化作为明确的接口行为变更发布并更新调用方。菜单栏和 export-json 迁移到查询/刷新接口；报告读取同一查询层。安装流程配置服务与可写数据目录，移除对开发者绝对仓库路径的依赖。

旧历史通过读取适配器暴露已知信息，标记 legacy provenance；不能补造旧记录没有保留的新字段、原始响应或账户信息。旧 cache 仅用于迁移期间带 stale 标识的展示，不能当成新成功采集。

## 分阶段交付

1. 数据契约：版本化观测、Claude 完整字段保留、其他来源适配、脱敏原始记录及旧历史读取兼容。
2. 可靠采集：独立协调进程、持久冷却、互斥、状态记录、launchd 和现有采集入口迁移。
3. 通用查询：新 MCP/CLI 接口、原始与聚合历史、分页、质量信息、菜单栏和报告接入。

三阶段共同构成首个通用版本。每阶段实施计划单独明确验收与依赖，不能把只补字段宣称成整体完成。

## 验收

- 含 scoped limit、美元额度、breakdown、新对象键和 null 的 fixture 均可无损获取其脱敏信息；没有合成不真实的绝对用量。
- 重排 limits 数组、修改展示名不会改变已有可识别额度 ID；已知重复字段不重复展示或求和。
- 三个 MCP 客户端和菜单栏并发刷新，同一来源只执行一次实际采集；冷却期间及重启后不提前请求。
- 关闭菜单栏和 MCP 后服务仍采集；在机器清醒联网、无冷却的测试区间内符合配置周期。
- 可区分不变的成功观测、缓存读取、采集失败、服务离线和存储失败；休眠或历史缺失不产生伪样本。
- raw 查询往返保持观测数值与时间；分页无重复遗漏；聚合不跨账户、单位或已知重置周期混算。
- 401/403、429、超时、畸形响应、写盘失败与崩溃尾行具有可检查的结构化状态。
- 原始落盘与工具输出不含 fixture 中注入的凭证；原始记录关闭或过期时明确说明不可用原因。
- 旧历史、旧查询工具和报告继续可用；旧数据缺少的信息保持未知。
- 通用调度与查询测试无需 macOS/真实凭证；来源平台能力缺失时有明确错误。限流验收使用模拟来源，不靠密集请求真实接口验证。

## 审阅结论

核心边界、观测与推导区分、未知字段策略、缓存与采集语义、兼容接口和验收已明确。上游字段真实语义、账户识别能力和来源支持平台需要在实现时用脱敏 fixture 与适配器能力说明验证，不应以猜测填充。实现前需用户确认本文，再编写实施计划。
